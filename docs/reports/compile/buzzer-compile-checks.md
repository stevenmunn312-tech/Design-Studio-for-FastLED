# Buzzer compile checks

> **Status: complete.** The KY-012 fixture passed on classic ESP32 on 1 October
> 2026, and the KY-006 fixtures passed on classic ESP32 and the Arduino UNO on
> 8 October 2026. This is compile evidence only; both buzzers remain
> experimental in the [support matrix](../../release/beta-support-matrix.md)
> until a recorded bench run exists.

The fixtures come from real Studio graphs. In the KY-012 one, a `ButtonInput` on
GPIO 4 feeds the Sound input of a `BuzzerOutput` on GPIO 26, with a solid colour
on an LED output to keep that alive. Fixture generation refuses a sketch that
does not contain exactly one buzzer write, one silent-level latch and one
output-mode call for the pin. The KY-012 is a plain `digitalWrite`, so there is
no library to exclude.

The KY-006 fixtures add a `PotInput` through a `MapRange` (200 to 4000 Hz) into
the passive buzzer's Pitch input. Generation refuses a sketch without exactly one
silent latch, one output-mode call, one `tone()` and one `noTone()` for the pin,
or with a level write. `buzzer-passive` uses classic ESP32 pins; the two UNO
fixtures put the buzzer on pin 8, and `buzzer-passive-ir-uno` adds an
`IRRemoteInput` on pin 2. That one exists because IRremote's receive timer on the
UNO is the same Timer2 that `tone()` uses; the two link together (IRremote uses
the other compare vector), and the generated sketch calls
`IrReceiver.restartTimer()` after each `noTone()`, which this fixture proves
compiles. Graph Health warns that the remote cannot hear while a tone plays.

The buzzer is generated by the normal sketch generator only, so there are no
slideshow or player fixtures.

## Reproduce

From the repository root:

```powershell
npm run gen:compile-fixtures -- buzzer
python scripts/compile-fixtures/compile-presence-smoke.py arduino-cli backend/sketches/buzzer-fixtures/buzzer.ino --fqbn esp32:esp32:esp32 --tag esp32 --label touchpad
python scripts/compile-fixtures/compile-presence-smoke.py arduino-cli backend/sketches/buzzer-fixtures/buzzer-passive.ino --fqbn esp32:esp32:esp32 --tag esp32 --label touchpad
python scripts/compile-fixtures/compile-presence-smoke.py arduino-cli backend/sketches/buzzer-fixtures/buzzer-passive-uno.ino --fqbn arduino:avr:uno --tag uno --label touchpad
python scripts/compile-fixtures/compile-presence-smoke.py arduino-cli backend/sketches/buzzer-fixtures/buzzer-passive-ir-uno.ino --fqbn arduino:avr:uno --tag uno --label touchpad
```

The runner uses the helper's real `_compile_upload` path and never flashes. It
writes a log and JSON report beside the generated sketch.
`backend/sketches/` is gitignored, so this page is the durable result. Run
compiles one at a time: they share one arduino-cli workspace per label, and two
runs at once, or a run killed part-way, leave a truncated cached object that
fails the next link with `ld: final link failed: file truncated`.

Toolchain: arduino-cli 1.5.1, ESP32 core 3.3.11 and FastLED 3.10.5. Target:
`esp32:esp32:esp32` with the helper's `huge_app` partition setting.

Source hash: `buzzer` `336341d1`.

## KY-006 result, 8 October 2026

Toolchain: arduino-cli 1.5.1, ESP32 core 3.3.11, Arduino AVR core 1.8.8,
FastLED 3.10.5 and IRremote 4.7.1. The ESP32 target is `esp32:esp32:esp32` with
the helper's `huge_app` partition setting.

| Fixture | Target | Source hash | Result | Flash | RAM |
| --- | --- | --- | --- | --- | --- |
| buzzer-passive | `esp32:esp32:esp32` | `a94a63f8` | pass | 407,095 / 3,145,728 (12%) | 27,972 / 327,680 (8%) |
| buzzer-passive-uno | `arduino:avr:uno` | `6e3c1c69` | pass | 7,832 / 32,256 (24%) | 746 / 2,048 (36%) |
| buzzer-passive-ir-uno | `arduino:avr:uno` | `2bfd0bd9` | pass | 9,838 / 32,256 (30%) | 1,007 / 2,048 (49%) |

A probe of the UNO sketch on the Arduino Due (`arduino:sam:arduino_due_x`, SAM
core 1.6.12) failed. The SAM core has no `tone()`, but the build also failed
inside FastLED 3.10.5's own headers (`'__is_trivially_copyable' was not declared
in this scope` in `fl/stl/type_traits.h`), so it says nothing particular about
the buzzer. No LED sketch builds on the Due's own compiler, and the Due was
withdrawn the same day
([IR compile record](ir-compile-checks.md#arduino-due-on-arduino-cli-8-october-2026)).
