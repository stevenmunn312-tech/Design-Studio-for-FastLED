# DFPlayer Mini compile checks

> **Status: complete.** The DFPlayer Mini fixture passed on classic ESP32 on
> 8 October 2026. This is compile evidence only; the module remains experimental
> in the [support matrix](../../release/beta-support-matrix.md) until a recorded
> bench run exists. No module has been played.

The fixture comes from a real Studio graph. A `ButtonInput` on GPIO 4 drives
the Play input of `DFPlayerOutput`. A solid colour drives an LED output.
Fixture generation refuses a sketch without the 9600 baud UART open, the
microSD device-select command, the `/mp3` play command and the active-low BUSY
reading that publishes Playing.

The DFPlayer Mini is generated by the normal sketch generator only. The
slideshow and SD-player templates do not evaluate arbitrary output devices, so
there are no fixtures for those paths. The module plays files from its own
microSD card. It does not replace the music-sync SD show path.

## Reproduce

From the repository root:

```powershell
npm run gen:compile-fixtures -- dfplayer
python scripts/compile-fixtures/compile-presence-smoke.py arduino-cli backend/sketches/dfplayer-fixtures/dfplayer.ino --fqbn esp32:esp32:esp32 --tag esp32 --label dfplayer
```

The runner uses the helper's real `_compile_upload` path and never flashes. It
writes a log and JSON report beside the generated sketch. `backend/sketches/`
is gitignored, so this page is the durable result. Run compiles one at a time;
they share one arduino-cli workspace.
